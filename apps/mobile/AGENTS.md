This is an Expo/React Native mobile application. Prioritize mobile-first patterns, performance, and cross-platform compatibility. `README.md` beside this file has the layout; `CONTRIBUTING.md` at the repo root has the rule that every user-facing change to `apps/client-web` ships with its counterpart here.

## Expo has changed: do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt, an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Commands

Run these in `apps/mobile` unless noted.

```bash
npx expo install <package>          # ALWAYS use instead of npm add: resolves SDK-compatible versions
npx expo start                      # start the dev server
npm run typecheck                   # tsc --noEmit
npx vitest run --project mobile-ui  # component tests (from the repo root)
npm test                            # the whole suite, including the parity gate (from the repo root)
npx expo-doctor                     # diagnose dependency and config issues
npx expo install --fix              # fix incompatible package versions
```

Run the typecheck and the tests before declaring any task done.

## Navigation

The app does not use Expo Router. `App.tsx` chooses between pairing, the projects list, About and an open project's shell (`src/AppShell.tsx`); inside a project, `src/nav.tsx` is a stack of screens over the sessions list. Add a screen there, not as a route file.

## Building

The release APK is built locally with `scripts/build-android.sh`, without an Expo account or EAS; `README.md` has how. During development, `npx expo run:android` makes a development build. Expo Go cannot run the app: it uses native modules Expo Go does not bundle.

## Rules

- `android/` and `ios/` are generated by `npx expo prebuild` and ignored by git. Never create or edit them by hand: configure native behavior in `app.json` and the config plugins in `plugins/`.
- Logic and strings both clients use live in `packages/client-core` and `packages/shared` and are imported, never copied. The parity gate (`test/parity-gate.test.ts`) fails on a copy.
- Prefer recommended Expo modules over third-party libraries, and check your available skills before adding dependencies. Docs: https://docs.expo.dev/versions/latest/index.md
